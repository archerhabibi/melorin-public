# Customer Catalog Contract (B4.1)

> نسخه 1.0 · Parent: Master 2.8 / Website 1.9 / Customer Profile 1.0 · وضعیت: CANONICAL
> دامنه: `GET /` (`website[.store].home`)، `GET /products/{product}` (`website[.store].products.show`)، و منوی «🛒 خرید اکانت» در ربات اصلی و ربات نماینده.
> **بدون Migration و بدون تغییر Schema.** خرید، Checkout و قیمت‌گذاری نماینده تغییر نکرده‌اند.

## C1. لایه‌ها

| لایه | کلاس | نقش |
|---|---|---|
| Core | `Catalog\ProductCatalogService` | `catalog` (فهرست + فیلتر + مرتب‌سازی)، `find` (یک تعرفه)، `alternatives` (جایگزین هم‌سبد) |
| Core | `Catalog\CatalogQuery` | پاک‌سازی ورودی عمومی (`q`, `category`, `sort`, `available`) و برچسب‌های مرتب‌سازی |
| Core | `Catalog\CatalogItem` / `CatalogCategory` / `Catalog` | DTOهای فقط‌خواندنی (قیمت نهایی، ظرفیت، برچسب مدت/حجم) |
| Core | `Catalog\CatalogText` | نرمال‌سازی متن جست‌وجو (خالص) |

**یک منبع حقیقت:** سایت، ربات اصلی و ربات نماینده یک فهرست را از یک سرویس می‌گیرند؛ تفاوتشان فقط ظاهر است.

## C2. قاعده‌ی دیده‌شدن

- **Main:** تعرفه‌ی `active` در سبدِ `active`. (سبد بدون تعرفه‌ی قابل‌نمایش نمایش داده نمی‌شود.)
- **فروشگاه نماینده:** فقط مدل opt-in همان نماینده: نمایندگی فعال، تعرفه و سبد فعال، سبد برای نمایندگان باز (`available_to_resellers`)، سبد توسط خود نماینده بسته نشده، و قیمتِ فعالِ خود نماینده وجود دارد. فهرست روی `ResellerPricingService::sellableProducts` سوار است و `find` روی `isSellable`؛ **قاعده دوباره‌نویسی نشده** و یک تست Parity تضمین می‌کند فهرست با Guard خرید هیچ‌وقت از هم جدا نشود.
- **تغییر رفتار (اصلاح باگ):** تا B3.5 صفحه‌ی تعرفه در فروشگاه اصلی برای تعرفه‌ی «سبد بسته» باز می‌شد ولی خرید در Core رد می‌شد. اکنون مثل ناموجود **404** است (صفحه‌ی تعرفه، Checkout و Guest Checkout).
- نامرئی = ناموجود: در سایت 404؛ در ربات «این تعرفه دیگر در دسترس نیست». وجود تعرفه‌ی غیرفعال از بیرون قابل‌حدس نیست.

## C3. قیمت

قیمت **نهایی از Core** است: Main = `main_price`، نماینده = `customers_price` همان نماینده. `reseller_price` و قیمت نماینده‌ی دیگر هرگز دیده نمی‌شود. Channel هیچ قیمتی محاسبه نمی‌کند.

## C4. ظرفیت (فقط نمایش)

`sale_limit` / `units_sold` ⇒ `remaining`، `isSoldOut` (باقی‌مانده = 0)، `isLowStock` (۱ تا ۵).
- **ظرفیت تکمیل دیده می‌شود** (نشان «ظرفیت تکمیل»)، پنهان نمی‌شود: مشتری باید بداند تعرفه وجود دارد. صفحه‌ی تعرفه دکمه‌ی خرید ندارد و تعرفه‌های جایگزین پیشنهاد می‌دهد؛ در ربات کلیک روی آن پیام می‌گیرد و سفارشی ساخته نمی‌شود.
- مرجع واقعی ظرفیت همچنان `PurchaseGuard` و رزرو اتمیک `PurchaseService` است؛ نمایش ممکن است نسبت به یک خرید هم‌زمان کهنه باشد و بی‌خطر است.
- «موجودی محدود» برای `remaining ≤ 5` نمایش داده می‌شود (عدد دقیق، فقط وقتی محدود است).
- حجم نامحدود: `traffic_gb` خالی یا ≤ 0 (همان قاعده‌ی `Account`) ⇒ «نامحدود».

## C5. جست‌وجو، فیلتر، مرتب‌سازی (GET، بدون نوشتن)

| پارامتر | قاعده |
|---|---|
| `q` | trim، حذف نویسه‌ی کنترلی/صفر-عرض/جهت‌دهی، فاصله‌ی پیاپی ⇒ یکی، سقف ۶۰ نویسه. همه‌ی واژه‌ها باید در «نام تعرفه + نام سبد» باشند (AND). مقایسه با نرمال‌سازی: ارقام فارسی/عربی ⇒ لاتین، «ي/ك» عربی ⇒ «ی/ک»، حذف نیم‌فاصله و کشیده. `%` `_` و SQL فقط متن‌اند (مقایسه در PHP، نه LIKE). |
| `category` | عدد مثبت؛ غیر از آن نادیده. سبد ناموجود ⇒ «نتیجه‌ای نیست». |
| `sort` | `default` (گروه‌بندی بر اساس سبد)، `price_asc`، `price_desc`، `duration` (بیشترین مدت)، `traffic` (بیشترین حجم؛ نامحدود از همه بیشتر). هر مقدار دیگر ⇒ `default`. غیرپیش‌فرض ⇒ یک فهرست سراسری. |
| `available` | `1/true/on/yes` ⇒ فقط تعرفه‌های دارای ظرفیت. |

- مقدار نامعتبر یا آرایه‌ای (`q[]=`) **هیچ‌وقت خطا نمی‌دهد**؛ به پیش‌فرض برمی‌گردد (کاتالوگ عمومی است).
- ظرفیت‌تکمیل‌ها همیشه آخر هر فهرست هستند؛ تساوی با شناسه شکسته می‌شود (ترتیب پایدار).
- منوی «سبد فروش» همیشه همه‌ی سبدهای قابل‌نمایش را (با تعداد) نشان می‌دهد، نه فقط نتیجه‌ی فیلتر.
- صفحه‌ی فیلترشده/مرتب‌شده `noindex,follow` است؛ صفحه‌ی ساده ایندکس می‌شود.
- پیام‌ها: کاتالوگ خالی ≠ «نتیجه‌ای نیست»؛ دومی لینک «پاک‌کردن فیلترها» دارد.

## C6. کارایی

فهرست فروشگاه نماینده با **تعداد ثابتی Query** ساخته می‌شود (قیمت‌ها یک‌جا خوانده می‌شوند؛ قبلاً هر تعرفه یک Query قیمت می‌زد). تست N+1 این را قفل می‌کند. صفحه‌بندی ندارد (D-20).

## C7. ربات

- «🛒 خرید اکانت»: سبدها از `catalog()->categories`؛ لیست تعرفه از همان آیتم‌ها (قیمت = همان قیمت سایت).
- برچسب دکمه مشترک بین دو ربات: `⛔ … · ظرفیت تکمیل` یا `… · N عدد مانده`.
- سبد/تعرفه‌ای که دیگر دیده نمی‌شود (دکمه‌ی پیام قدیمی) ⇒ پیام ملایم، نه خطا و نه خرید.
- مسیر خرید، کیف پول و نام‌گذاری بدون تغییر.

## C8. فقط خواندن

Catalog هیچ‌چیز نمی‌نویسد (نه سفارش، نه CustomerAccount، نه Audit). تست «reading writes nothing» آن را قفل می‌کند.
