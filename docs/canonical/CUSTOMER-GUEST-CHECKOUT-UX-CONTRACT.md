# Customer Guest Checkout UX Contract (B4.3)

> نسخه 1.0 · Parent: Master 2.8 §3 / Website 1.9 §5 / Catalog 1.0 · وضعیت: CANONICAL
> دامنه: `GET|POST /products/{product}/guest-checkout`، `GET /guest-checkout/pending`، و CTAهای خرید در صفحه‌ی تعرفه (Main و `/store/{slug}`).
> **بدون Migration، بدون Route جدید، بدون تغییر Core.** قواعد داده‌ی Guest (G2/G3/G5/G7/G9) دست‌نخورده است؛ فقط تجربه‌ی کاربری.

## U1. قواعد ثابت (تغییر نکرده)
email تنها فیلد الزامی (G2)؛ هیچ User/CustomerAccount/Wallet/Order از Guest ساخته نمی‌شود (G3)؛ نشست فقط در همان Context معتبر است (G5)؛ تصادم با User موجود ⇒ Login + Audit، بدون Merge/Login خودکار (G7)؛ TTL ۴۵ دقیقه و Retention ۶۰ روز (G9).

## U2. مراحل
`x-ui.steps`: «۱ اطلاعات ← ۲ ورود یا ثبت‌نام ← ۳ پرداخت». فرم = مرحله ۱، Pending = مرحله ۲. وضعیت فقط با رنگ منتقل نمی‌شود (عدد/✓، `aria-current="step"`، متن SR «مرحله‌ی N از M»).

## U3. فرم (مرحله ۱)
- Breadcrumb (تعرفه‌ها ← نام تعرفه ← خرید مهمان) و کارت «خلاصه‌ی خرید» (نام، سبد، مدت، حجم، قیمت نهایی Core، «N عدد باقی مانده» برای ۱..۵).
- فیلدها با `x-ui.field`: برچسب/`aria-invalid`/`aria-describedby` خودکار؛ `autocomplete` (email/name/tel)، `inputmode`، `dir="ltr"` برای ایمیل و تلفن.
- پیام اطمینان: پرداخت فقط بعد از ورود؛ تا قبل از آن حسابی ساخته و هزینه‌ای کسر نمی‌شود.
- میان‌بر «قبلاً ثبت‌نام کرده‌اید؟ ورود» (همان Context).

## U4. ویرایش اطلاعات (Prefill)
Pending لینک «ویرایش اطلاعات» دارد که همان فرم را باز می‌کند. فرم از **نشست Pending فعالِ همین مرورگر و همین Context** (Cookie رمزنگاری‌شده) پر می‌شود؛ `old()` بعد از خطا اولویت دارد. Submit نشست قبلی را باطل می‌کند (B2.3، یک نشست Pending). توکن نامعتبر/Context دیگر ⇒ هیچ داده‌ای پر نمی‌شود. (Prefill فرم **Login** همچنان ممنوع است؛ B2.3.)

## U5. ظرفیت تکمیل
- فرم/ثبت برای تعرفه‌ی `isSoldOut` ⇒ Redirect به صفحه‌ی همان تعرفه (جایگزین‌ها آنجاست) با پیام `warning`؛ **هیچ GuestCheckout ساخته نمی‌شود**.
- ظرفیت بعد از شروع نشست تمام شود ⇒ Pending به‌جای دکمه‌های ورود/ثبت‌نام پیام و «مشاهده‌ی تعرفه‌های جایگزین» نشان می‌دهد.
- مرجع واقعی ظرفیت همچنان `PurchaseGuard`/رزرو اتمیک است؛ این فقط UX است (C4).

## U6. صفحه‌ی تعرفه
دو CTA هم‌وزن («برای خرید وارد شوید» / «خرید به‌عنوان مهمان») با دکمه‌ی دیزاین‌سیستم و یک خط توضیح. Layout پیام `session('warning')` را نشان می‌دهد.

## U7. Out of scope
نرمال‌سازی `guest_phone` و تطبیق تصادم با فرم‌های قدیمی شماره (D-17)، OTP/تأیید ایمیل پیش از Pending، Google پیش از فرم (نیازمند Cookie/Session دو‌مرحله‌ای)، صفحه‌ی خطای اختصاصی برای نشست منقضی (فعلاً 404 با پیام)، B4.2 (قیمت‌گذاری)، B4.4 (پرداخت).
