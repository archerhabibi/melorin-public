# Reseller Branding Contract (B6.2)

> نسخه 1.0 · Parent: Master 2.8 / Website 1.9 / Reseller White Label 1.0 / Reseller Custom Domain 1.1 · وضعیت: CANONICAL
> دامنه: **لوگو و رنگ‌های برند فروشگاه نماینده** (خوانایی رنگ، لوگوی حالت تیره، Favicon، اندازه‌ی لوگو). **Migration کوچک و افزایشی** (`2026_10_09_000001`: دو ستون روی `reseller_website_settings`) و **بدون تغییر Purchase/Provisioning/Refund/Wallet/Payment/StoreContext**. Website همچنان فقط Channel است؛ هیچ Business Rule مالی در این فاز نیست.
> این سند **ادامه‌ی** `RESELLER-WHITE-LABEL-CONTRACT.md` است (منبع واحد `StoreBrand`، مسیر نوشتن `ResellerBrandingService`، قواعد لوگو W3 همه برقرارند)؛ فقط شکاف‌های B6.2 را می‌بندد.

## B1. وضعیت قبل از B6.2 (صادقانه)
از قبل وجود داشت: لوگوی اصلی (آپلود/حذف امن)، یک رنگ اصلی با متن خودکار روی دکمه (`onColor`)، رنگ primary پنل، `theme-color`. **شکاف‌ها:** (۱) رنگ برند **همان‌طور که هست** به‌عنوان رنگ *متن/لینک* هم استفاده می‌شد: برند زرد روی سفید و برند سرمه‌ای روی حالت تیره ناخوانا بود (حالت تیره فقط یک ترکیب ۶۰٪ با سفید بود، بدون تضمین contrast)؛ (۲) لوگو در سربرگ در یک مربع `۸×۸` له می‌شد، پس لوگوی افقی تقریباً نامرئی بود؛ (۳) لوگوی روشن/سفید روی حالت تیره قابل‌تنظیم نبود؛ (۴) Favicon اختصاصی نبود؛ (۵) نماینده راهی برای فهمیدن خوانایی رنگش نداشت.

## B2. رنگ‌ها
- **رنگ برند (`--brand`) دست‌نخورده می‌ماند** و فقط برای پس‌زمینه‌ی دکمه‌ها/حاشیه‌ها/`theme-color`/رنگ primary پنل است (همان قبلی؛ `onColor` و `panelColor` بدون تغییر).
- دو رنگ **مشتق** برای متن/لینک (`BrandColor::textOnLight` / `textOnDark`، `StoreBrand::textColor()` / `darkTextColor()`): اگر رنگ روی سطح مبنا contrast ≥ **۴.۵** (WCAG AA) داشته باشد **دست‌نخورده** می‌ماند؛ وگرنه در گام‌های ریز (۵٪) به سمت سیاه (سطح روشن `#ffffff`) یا سفید (سطح تیره `#14181f` = `--c-surface`) می‌رود تا **نزدیک‌ترین رنگ خوانا** انتخاب شود (هویت رنگ تا حد ممکن حفظ می‌شود). همیشه پایان می‌پذیرد (سیاه/سفید خالص). ورودی نامعتبر ⇒ رنگ پیش‌فرض (هرگز به CSS نشت نمی‌کند).
- تنها نقطه‌ی چاپ: Partial `website/partials/brand-head.blade.php` (Layout وب و صفحه‌ی نتیجه‌ی پرداخت): `--brand`، `--brand-contrast`، `--brand-text`، `--brand-text-dark`. قالب رشته‌ی دو متغیر قبلی بدون تغییر ماند.
- CSS: `.text-brand`/`.link-brand` از `--brand-text` (روشن) و `--brand-text-dark` (تیره) می‌خوانند؛ مقدارِ پیش‌فرضِ `var()` همان رفتار قبلی است (کامپوننتی که متغیر را ندارد نمی‌شکند).
- **فرم تنظیمات:** گزارش خوانایی فقط‌راهنما (`BrandColor::report`): نسبت contrast متن دکمه و اینکه متن/لینک در هر حالت اصلاح می‌شود یا نه. هیچ رنگی رد/قفل نمی‌شود.

## B3. لوگو
- سربرگ: **ارتفاع ثابت `h-8`، عرض خودکار، حداکثر `10rem`**، `object-contain`؛ لوگوی افقی دیگر له نمی‌شود (قبلاً `۸×۸`). پیش‌نمایش فرم هم همین‌طور.
- **لوگوی حالت تیره** (اختیاری، ستون `logo_dark_path`): قیود فایل = لوگوی اصلی (PNG/JPG/WebP، ≤ ۱ مگابایت، ≤ ۲۰۰۰×۲۰۰۰). وقتی هست، هر دو `<img>` چاپ می‌شوند و CSS با `data-theme` یکی را نشان می‌دهد (بدون JS و بدون فلاش، چون `theme-init.js` پیش از رندر تم را می‌گذارد)؛ وقتی نیست فقط یک `<img>` چاپ می‌شود (رفتار قبلی). **فقط کنار لوگوی اصلی معنی دارد:**
  - آپلود لوگوی تیره وقتی لوگوی اصلی نه هست و نه همین درخواست می‌گذارد ⇒ `ValidationException` روی `logo_dark` (چیزی ذخیره نمی‌شود).
  - حذف لوگوی اصلی (بدون آپلود جدید) نسخه‌ی تیره را هم **حذف** می‌کند؛ تنها نمی‌ماند. آپلود جدید بر حذف مقدم است (W3) و نسخه‌ی تیره را نگه می‌دارد.
  - ردیف یتیم (فقط `logo_dark_path`) توسط `StoreBrandResolver` نادیده گرفته می‌شود (Layout و پنل).
- پنل نماینده: `darkModeBrandLogo` از همان منبع (`logoDarkUrl`).

## B4. Favicon (اختصاصی)
- ستون `favicon_path`؛ قیود: **PNG/WebP**، **مربعی** (`ratio=1`)، **۳۲ تا ۵۱۲ پیکسل**، ≤ ۲۰۰ کیلوبایت. SVG/ICO عمداً پذیرفته نمی‌شود (همان سیاست لوگو: بدون محتوای فعال).
- پوشه‌ی جدا `reseller-favicons/{reseller_id}`. `<link rel="icon">` فقط وقتی نماینده آپلود کرده؛ Main و نمایندگان بدون آن **دقیقاً مثل قبل**. روی صفحه‌ی نتیجه‌ی پرداخت (فقط با Payment واقعی) و پنل نماینده (`->favicon()`) هم همان.
- مسیر فایل‌ها `/storage/...` است و روی دامنه‌ی اختصاصی B6.1 هم سرو می‌شود (مسیر زیرساختی بازنویسی نمی‌شود).

## B5. نوشتن (تنها مسیر: `ResellerBrandingService`)
- سه «دارایی تصویری» (`logo`، `logo_dark`، `favicon`) یک الگوی واحد دارند: **فایل تازه اول ذخیره، فایل قبلی بعد از موفقیت DB پاک؛ خطا ⇒ همه‌ی فایل‌های تازه پاک و قبلی‌ها دست‌نخورده**؛ حذف جدا برای هرکدام؛ بدون تغییر واقعی ⇒ نه نوشتن، نه Audit (حذفِ چیزی که وجود ندارد هم بی‌اثر است و ردیف نمی‌سازد).
- امضای `update()` سازگار با قبل است (پارامترهای تازه در انتها و اختیاری).
- Audit `reseller.branding.updated` با **نام ستون‌های تغییرکرده** (`logo_dark_path`، `favicon_path`)؛ مسیر فایل ثبت نمی‌شود.
- دسترسی همچنان `ManageController::authorize` (ادمین/مالک همین نماینده؛ دیگران 403 و هیچ فایلی ذخیره نمی‌شود).

## B6. تصمیم‌ها / محدودیت‌ها (صادقانه)
- **رنگ ثانویه/Accent و رنگ جداگانه‌ی حالت تیره** عمداً اضافه نشد: یک رنگ برند + مشتق‌های خودکار contrast کافی و بی‌خطر است؛ رنگ دوم طراحی/قرارداد جدا می‌خواهد (و هر رنگ اضافه، سطح جدیدی برای ناخوانایی است).
- Contrast مبنا دو سطح ثابت (`#ffffff` و `#14181f`) است. متنی که روی `bg-surface-2`/کارت‌های رنگی می‌آید کمی متفاوت است؛ این مبنا همان سطح اصلی صفحه است و تغییر توکن‌ها (B1.1) باید با ثابت‌های `BrandColor::LIGHT_SURFACE/DARK_SURFACE` هم‌خوان بماند.
- لوگو بازنمونه‌گیری/فشرده نمی‌شود (همان فایل آپلودشده سرو می‌شود)؛ فقط سقف حجم/ابعاد.
- Favicon فقط PNG/WebP است؛ مرورگرهای قدیمی که فقط `.ico` می‌خواهند آیکن اختصاصی نمی‌بینند.
- لوگو/Favicon در **ایمیل‌ها، ربات نماینده و صفحه‌ی ورود Filament** استفاده نمی‌شود (جزو B6 بعدی/Out of scope W8).
- فایل‌های خارج از `public` disk (CDN/Object Storage) تغییری نکرد؛ URL از `Storage::disk('public')->url()` است.

## B7. تست
`BrandTextColorTest` (۷؛ contrast همه‌ی نمونه‌ها، رنگ کافی دست‌نخورده، جهت اصلاح، حداقلی‌بودن، رنگ‌های حدی، ورودی نامعتبر، `mix`، `report`) + `BrandAssetsTest` (۱۵؛ لوگوی تیره: ذخیره/رد بدون لوگوی اصلی/افزودن بعدی/حذف زنجیره‌ای/حذف تکی/جایگزینی هم‌زمان/ردیف یتیم؛ Favicon: پوشه، جایگزینی/حذف و پاک‌شدن فایل قبلی؛ حذفِ ناموجود بی‌اثر؛ شکست DB با پاک‌شدن همه‌ی فایل‌های تازه؛ Audit فقط نام فیلد؛ قوانین Favicon/لوگوی تیره؛ Migration ایدمپوتنت) + `ResellerBrandAssetsWebTest` (۱۷؛ متغیرهای رنگ، Main، رنگ نامعتبر، منبع CSS، لوگوی غیرمربع، یک/دو تصویر، تیره‌ی یتیم، Favicon، صفحه‌ی پرداخت، آپلود هم‌زمان، خطای فیلد، ۴۰۳ بدون ذخیره، گزارش خوانایی، چک‌باکس حذف) + `ResellerBrandPanelAssetsTest` (۳؛ پنل و عدم نشت بین فروشگاه‌ها). تست‌های قبلی (`ResellerBrandingServiceTest`، `ResellerWhiteLabelTest`، `ThemeEngineTest`، `BrandColorTest`، …) **بدون تغییر** سبز ماندند.
**جهش عمدی (۶ مورد، همه گرفته شد):** حذف زنجیره‌ی لوگوی تیره، حذف پاک‌سازی فایل تازه هنگام خطا، وارونه‌شدن جهت اصلاح رنگ، نمایش تیره‌ی یتیم، حذف اعتبارسنجی «تیره بدون اصلی»، پایین‌آوردن حداقل contrast.
**اجرا شد:** کل مجموعه روی SQLite (۱۲۹۸ سبز، ۵ Skip) و `vite build` (قواعد جدید در CSS خروجی هست). **اجرا نشده:** MySQL واقعی، مرورگر واقعی (دیدن لوگوی تیره/تغییر تم و Favicon روی تب)، آپلود واقعی تصویر روی دیسک تولید.
